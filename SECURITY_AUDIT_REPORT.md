# Отчет по безопасности API - Ревизия эндпоинтов

**Дата проведения:** 26 января 2026  
**Статус:** Требуется исправление критичных уязвимостей

---

## 🔴 КРИТИЧНЫЕ УЯЗВИМОСТИ

### 1. Отсутствие проверки доступа к проекту в эндпоинтах документов

**Файл:** `back/app/api/v1/endpoints/documents.py`

**Проблемы:**
- `GET /documents/{document_id}` (строка 850) - нет проверки, что пользователь имеет доступ к проекту документа
- `GET /documents/{document_id}/download` (строка 2013) - проверка только `uploaded_by`, без проверки доступа к проекту
- `GET /documents/` (строка 253) - фильтрация по `project_id` без проверки членства в проекте

**Риск:** Пользователь может получить доступ к документам чужого проекта, подставив `document_id`.

**Пример атаки:**
```
GET /api/v1/documents/123
Authorization: Bearer <токен_другого_пользователя>
```

**Решение:** Добавить проверку членства пользователя в проекте документа через `ProjectMember`.

---

### 2. Отсутствие проверки доступа к проекту в эндпоинтах трансмитталов

**Файл:** `back/app/api/v1/endpoints/transmittals.py`

**Проблемы:**
- `GET /transmittals/{transmittal_id}` (строка 351) - нет проверки доступа к проекту
- `POST /download/generate/{transmittal_id}` (строка 27 в download.py) - нет проверки доступа к проекту трансмиттала

**Риск:** Можно создать ссылку на скачивание для чужого трансмиттала.

**Пример атаки:**
```
POST /api/v1/download/generate/999
Authorization: Bearer <токен_пользователя>
```

**Решение:** Добавить проверку членства пользователя в проекте трансмиттала.

---

### 3. Недостаточная проверка прав в скачивании документов

**Файл:** `back/app/api/v1/endpoints/documents.py:2013`

**Проблема:**
```python
if not current_user.is_admin and latest_revision.uploaded_by != current_user.id:
    raise HTTPException(status_code=403, detail="Нет прав доступа к документу")
```

Проверяется только `uploaded_by`, без проверки членства в проекте.

**Риск:** Участник проекта не может скачать документ, если не является загрузчиком. Или наоборот - можно получить доступ к документу, если знать ID загрузчика.

**Решение:** Заменить проверку на проверку членства в проекте (как в `download_document_revision`).

## 🟡 СРЕДНИЕ УЯЗВИМОСТИ

### 4. Публичный эндпоинт с информацией о трансмиттале

**Файл:** `back/app/api/v1/endpoints/download.py:275`

**Эндпоинт:** `GET /download/{token}/info` - публичный, без аутентификации

**Проблема:** Возвращает информацию о трансмиттале (номер, название, количество документов) по токену.

**Риск:** Утечка информации о трансмиттале без скачивания файлов.

**Решение:** Ограничить информацию или сделать эндпоинт приватным.

---

### 5. Отсутствие rate limiting на публичных эндпоинтах

**Файл:** `back/app/api/v1/endpoints/download.py:165`

**Эндпоинт:** `GET /download/{token}` - публичный

**Проблема:** Нет ограничения частоты запросов.

**Риск:** 
- Перебор токенов (brute force)
- DoS атаки

**Решение:** Добавить rate limiting (например, через `slowapi` или nginx).

---

### 6. Недостаточная валидация параметров в генерации ссылок

**Файл:** `back/app/api/v1/endpoints/download.py:27`

**Проблема:** Параметры `expires_in_days` и `max_downloads` не валидируются (можно задать отрицательные или очень большие значения).

**Риск:** Создание ссылок с некорректными параметрами.

**Решение:** Добавить валидацию:
- `expires_in_days`: 1-365 дней
- `max_downloads`: 1-1000

## 🟢 НИЗКИЕ / ПОТЕНЦИАЛЬНЫЕ ПРОБЛЕМЫ

### 7. Отсутствие проверки доступа к проекту в некоторых эндпоинтах проектов

**Файл:** `back/app/api/v1/endpoints/projects.py`

**Проблемы:**
- Многие эндпоинты проверяют существование проекта, но не всегда проверяют членство пользователя
- `GET /projects/{project_id}/members/` (строка 1042) - может раскрывать список участников без проверки доступа

**Решение:** Добавить проверку членства в проекте для всех эндпоинтов, работающих с данными проекта.

---

### 8. Информационная утечка через ошибки

**Проблема:** Некоторые эндпоинты возвращают детальные сообщения об ошибках, которые могут раскрывать структуру БД.

**Примеры:**
- "Трансмиттал не найден" vs "Нет прав доступа" - разница может раскрывать существование ресурса

**Решение:** Унифицировать сообщения об ошибках (не раскрывать существование ресурсов).

---

### 9. Отсутствие проверки CSRF для операций изменения

**Проблема:** Нет защиты от CSRF для операций POST/PUT/DELETE.

**Решение:** Добавить CSRF токены или использовать SameSite cookies.

## 🔍 ПРИМЕРЫ АТАК

### 1. IDOR (Insecure Direct Object Reference)

**Атака:**
```
GET /api/v1/documents/123
Authorization: Bearer <токен_пользователя_из_другого_проекта>
```

**Результат:** Если нет проверки доступа к проекту, может вернуть документ из чужого проекта.

**Защита:** Проверка членства в проекте через `ProjectMember`.

---

### 2. Перебор токенов

**Атака:**
```
GET /api/v1/download/TOKEN1
GET /api/v1/download/TOKEN2
...
```

**Результат:** Если токены предсказуемы, можно найти валидные ссылки.

**Защита:** 
- ✅ Токены генерируются через `secrets.token_urlsafe()` (хорошо)
- ⚠️ Нужен rate limiting для предотвращения перебора

---

### 3. Создание ссылок на чужие трансмитталы

**Атака:**
```
POST /api/v1/download/generate/999
Authorization: Bearer <токен_пользователя>
Body: {"expires_in_days": 365, "max_downloads": 1000}
```

**Результат:** Создание ссылки на чужой трансмиттал, если нет проверки доступа.

**Защита:** Проверка членства в проекте трансмиттала.

## 🔧 РЕКОМЕНДУЕМЫЕ ИСПРАВЛЕНИЯ

### Создать helper-функцию для проверки доступа к проекту

```python
def check_project_access(
    db: Session,
    user: User,
    project_id: int,
    allow_admin: bool = True
) -> bool:
    """
    Проверяет, имеет ли пользователь доступ к проекту
    
    Args:
        db: Database session
        user: Текущий пользователь
        project_id: ID проекта
        allow_admin: Разрешить доступ администраторам
    
    Returns:
        True если есть доступ, иначе False
    """
    if allow_admin and user.is_admin:
        return True
    
    project_member = db.query(ProjectMember).filter(
        ProjectMember.project_id == project_id,
        ProjectMember.user_id == user.id
    ).first()
    
    return project_member is not None
```

### Использовать в эндпоинтах

```python
@router.get("/{document_id}")
async def get_document(
    document_id: int,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_active_user)
):
    document = db.query(Document).filter(Document.id == document_id).first()
    if not document:
        raise HTTPException(status_code=404, detail="Документ не найден")
    
    # Проверка доступа к проекту
    if not check_project_access(db, current_user, document.project_id):
        raise HTTPException(status_code=403, detail="Нет доступа к проекту")
    
    # ... остальной код
```
